# Relay Desktop

Прототип интерфейса Telegram Desktop на Rust и Slint.

## Запуск

Для авторизации задайте `TG_API_HASH` перед сборкой. API ID задан в `TG_API_ID`
в `src/telegram.rs`; при использовании своего приложения замените и его.
Без API hash программа собирается, но вход в Telegram недоступен.

Workflow `Build debug and release` собирает Windows x64 при push в `main`,
push тега `v*`, pull request и ручном запуске через Actions.
Готовые `.exe` и лицензии доступны в артефактах
`relay-desktop-windows-x64-debug` и `relay-desktop-windows-x64-release`.
Для авторизации в этих сборках добавьте repository secret `TG_API_HASH`.
Секреты недоступны в pull request из сторонних fork.

```sh
cargo run --locked
```

Для Windows нужна среда Rust MSVC с C++ Build Tools и Windows SDK.
На Linux используются X11 или Wayland. Например, для сборки на Debian/Ubuntu
нужны пакеты `build-essential pkg-config libfontconfig1-dev`.

Оформление открывается кнопкой меню слева от поиска. Доступны темы Telegram,
Material You и WinUI, светлая и тёмная схемы. Для Material доступны три акцента.
Это оформления, нарисованные Slint. Тема WinUI не использует нативный WinUI 3,
а Material использует подготовленные палитры вместо системной генерации цветов.

Настройки оформления сохраняются в
`%LOCALAPPDATA%/relay-desktop/preferences.json` на Windows и
`$XDG_CONFIG_HOME/relay-desktop/preferences.json` на Linux.
Если XDG_CONFIG_HOME отсутствует, используется `~/.config`.
Переменная `RELAY_CONFIG_DIR` задаёт другую папку настроек.

Работают поиск чатов, переключение переписки, черновики в пределах сеанса,
отправка текста и вставка эмодзи. Ctrl+K переводит фокус в поиск,
Enter открывает первый результат или отправляет текст.

Иконки Telegram и шрифты встроены в исполняемый файл: папка `ui` для запуска
скачанной сборки не нужна. Приложение использует полноценный рендерер Skia
со сглаживанием текста, фильтрацией изображений и круглой обрезкой аватаров.
По умолчанию Skia использует GPU; при недоступности GPU он сохраняет свой
полноценный CPU-рендеринг. Упрощённый Slint `renderer-software` в приложение не включён.
Маски иконок и контуры пузырей рисуются в разрешении
3× для экранов с масштабированием. Источники и лицензии перечислены в `licenses/NOTICE.md`.
Дополнительные команды открываются кнопкой ⋮ в чате, действия с сообщением —
правой кнопкой мыши по пузырю.

Подключены авторизация Telegram, история, отправка текста и файлов, просмотр фото.
Фото в переписке имеют встроенные превью, загружаемые для видимой части истории;
декодированные миниатюры ограничены бюджетом 24 МБ. Перед отправкой изображения
показывается его превью, подпись можно изменить в окне вложения.
Ответы показывают автора и цитату в пузыре и над полем ввода. Нажатие на цитату
переводит к оригиналу с подсветкой; отсутствующий оригинал запрашивается у Telegram.
Статус в заголовке показывает доступное Telegram время последнего посещения.
При скрытом времени остаётся приблизительный статус Telegram; локального слежения
для восстановления скрытого времени нет.
В Windows закрытие окна сворачивает приложение в трей. Значок открывает окно,
его меню содержит «Выйти». Если системная область уведомлений недоступна,
закрытие завершает приложение. В фоне нет опроса контактов и таймера опроса
интерфейсом: мост Telegram будит интерфейс только при поступлении событий.
Также доступен демонстрационный режим. Звонки ещё не реализованы.
Интерфейс воспроизводит основные размеры Telegram Desktop, но точное
пиксельное совпадение со всеми его экранами пока не достигнуто.

Проверка Rust-кода

```sh
cargo fmt --check
cargo clippy --locked -- -D warnings
cargo test --locked -j 1
```

Тест интерфейса использует Skia без Telegram и рабочего стола, проверяет наличие
иконок и круглую обрезку фото при масштабе 100%, 150% и 200%, а также светлую тему и узкое окно.
Если задать `RELAY_UI_SNAPSHOTS`, PNG-превью сохраняются в указанную папку.

## Профили и вложения

Нажатие на отправителя сообщения, заголовок чата или свой аватар открывает профиль.
Шапка перенесена из Telegram Desktop 7.4.1: фото по центру, сжатие при прокрутке,
ряд действий и информация о пользователе. Есть просмотр фото, копирование данных,
QR публичной ссылки и переключение уведомлений через Telegram. Публичные подарки
можно скрыть в настройках. Превью подарков статичные; **полное совпадение профилей
1:1 пока не достигнуто**. Источники, покрытие и ограничения:
[docs/telegram-profiles.md](docs/telegram-profiles.md).

Скрепка открывает системный выбор нескольких файлов; файлы можно перетащить в окно.
Проверка путей выполняется вне UI-потока. Перед отправкой можно удалить вложения
и изменить подпись. Вставка/копирование/вырезание используют TextInput и системный
буфер обмена; форматирование доступно через контекстное меню и Ctrl+B/I/U/M.
Развёрнутый редактор открывается явно через меню, а не при вставке нескольких строк.

## Плавность в развёрнутом окне

Для оценки производительности используйте **release**, а не debug-артефакт.
Кнопка разворачивания сохраняет обычный оконный режим с панелью задач;
эксклюзивный fullscreen не нужен. Windows использует Skia/D3D и синхронизацию
кадров с экраном, без постоянного таймера принудительной перерисовки.

- Невидимые, неподвижные строки истории отсекаются целиком при отрисовке.
  Во время отправки/получения отсечение строки выключается, чтобы не обрезать анимацию.
- Превью и цитаты запрашиваются после изменения видимой области, без повторного
  опроса каждые 80 мс. Обычные текстовые строки не запускают эти проверки.
- Telegram работает в отдельном Tokio runtime с 1–4 async workers. Декодирование
  изображений и уменьшение аватаров/превью выполняются в blocking pool
  (до четырёх потоков), а не в потоке UI. Маленькие превью не увеличиваются до 960px.
- Результаты фоновой работы применяются в UI порциями: до 32 событий или
  мягкого лимита 4 мс, затем продолжение через однократный таймер. Одно тяжёлое
  событие может превысить лимит; очередь не отбрасывается и не меняет порядок.

Для проверки FPS на своём GPU можно временно включить штатный счётчик Slint
в PowerShell перед запуском release `.exe`:

```powershell
$env:SLINT_DEBUG_PERFORMANCE = "refresh_lazy,overlay"
.\relay-desktop.exe
# После проверки, перед следующим запуском:
Remove-Item Env:SLINT_DEBUG_PERFORMANCE
```

Смотрите на показатель во время продолжительной прокрутки/анимации. В покое
низкий FPS нормален: приложению не нужно рисовать одинаковые кадры. Счётчик
тоже добавляет небольшие накладные расходы. Цель для 60 Гц — около 16,7 мс на
кадр; стабильные 60 FPS зависят от GPU, DPI, содержимого и нагрузки системы.
Headless PNG-тесты не измеряют Windows D3D/DWM presentation: они проверяют
геометрию при размерах рабочего окна до 3840×2080, анимации, длинную историю,
отсутствие повторных запросов в покое и обработку очереди фоновых событий.
